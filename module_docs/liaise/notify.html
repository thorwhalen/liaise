liaise.notify

Owner notification (A.7): one function posting to ntfy, and the one builder of what it says.

liaise has no owner-facing UI; ntfy (a plain HTTP POST) is the whole channel. Silent when unconfigured, because a package should not require a notification service just to run its tests or a first liaise run –once –dry-run.

No case content goes to the notifier. Anyone who knows an ntfy topic’s name can read it, so notice_body() is the only builder of a notification’s body. It names the subject, the case, the event and what liaise calls its cause (an error class, a gate filter, an exit code), and points at liaise case show. It never carries what an agent wrote (a draft, a reason, a summary), a message, or a command’s output: those stay on the case, where the operator reads them on their own machine. notice_title() is the only builder of a title, which goes out with the body: fixed text, the subject’s slug and the case ids, never a person’s name or address, an issue’s title or a report’s subject.

liaise.notify.CASE_SHOW_POINTER = 'see liaise case show {case_id}'

each case it names, or the status when it names none.

Where a notification points the operator for what it leaves out

liaise.notify.NOTICE_TITLES = mappingproxy({'escalation': '{cases} needs you', 'no channel to reach the reporter': 'no channel to reach the reporter of {cases}', 'message diverted by the gate': 'liaise: a draft for {cases} waits for you', 'send failed': 'liaise: a message for {cases} was not sent', 'effects held': "liaise: {cases}'s effects are held", 'deploy failed': 'liaise: {cases} landed but did not deploy', 'delivery raised an exception': 'liaise: delivering {cases} failed', 'run lost': 'liaise: {cases} run lost', 'run cancelled for a hold': "liaise: {cases}'s run was cancelled", 'error': 'liaise: {cases} {error_class}', 'start refused': 'liaise: {cases} needs you before work starts', 'daily cap reached': 'liaise: {subject} reached its daily cap', 'issue state unreadable': "liaise: {cases}'s issue cannot be read"})

{cases} (the case ids, else the subject’s slug), {subject} (the slug) and, for an error alone, {error_class}. Nothing else ever fills a title.

Type:

Each event’s notification title, in notice_title()’s fields

liaise.notify.notice_body(event: str, *, subject: str, case_ids: Iterable[str] = (), cause: str | None = None) → str[source]

The body of an operator notification about event: nothing a case holds.

A line each for the subject’s slug, the case ids (a batch deploy has several), the event (one of NOTICE_EVENTS) and its cause when there is one, then a CASE_SHOW_POINTER per case, or STATUS_POINTER without one. cause is a name liaise gives the cause: an error class, a gate filter, an exit code, a hold’s scope kind. Callers never pass text an agent wrote, a message, or a command’s output.

>>> print(notice_body(NOTICE_ERROR, subject="example-app",
...     case_ids=["example-app-1"], cause="timed_out"))
subject: example-app
case: example-app-1
event: error
cause: timed_out
see liaise case show example-app-1

Raises ValueError for an event outside NOTICE_EVENTS.

liaise.notify.notice_title(event: str, *, subject: str, case_ids: Iterable[str] = (), cause: str | None = None) → str[source]

The title of an operator notification about event: fixed text, the slug, the case ids.

A title is pushed with its body, and is held to the body’s rule and to a narrower one: it never names a person or an address, an issue’s title or a report’s subject, whatever the event. It is NOTICE_TITLES’s text for event, filled with the case ids, or the subject’s slug without any. cause is the one notice_body() gets: a title names it only for NOTICE_ERROR, where it must be one of liaise.errors.ERROR_CLASSES, and ignores it for every other event.

>>> notice_title(NOTICE_ERROR, subject="example-app", case_ids=["example-app-1"],
...     cause="timed_out")
'liaise: example-app-1 timed_out'

Raises ValueError for an event outside NOTICE_EVENTS, and for an error whose cause is not an error class.

liaise.notify.notify(title: str, body: str, *, priority: str = 'default', topic_env: str = 'LIAISE_NTFY_TOPIC', base_url: str = 'https://ntfy.sh') → bool[source]

POST body to the ntfy topic named by the topic_env environment variable.

Returns whether it actually sent. No-ops (returns False) when topic_env is unset. Never raises — a notification failure must not take down a run that otherwise succeeded. Build body with notice_body().
